# TAA epic completion evidence

The implementation for [epic #39](https://github.com/semihguresci/VulkanSceneRenderer/issues/39)
and issues #48 through #59 is delivered in [PR #60](https://github.com/semihguresci/VulkanSceneRenderer/pull/60).
TAA is opt-in, native resolution, and supports 1x forward/deferred raster with
rigid glTF, BIM and USD triangles. The [runtime contract](temporal-rendering.md)
describes coordinates, resource ownership, supported modes, controls and limits.

## Measurement environment

Windows x64, NVIDIA GeForce RTX 2080 SUPER, NVIDIA driver 591.86
(raw Vulkan driver version 2480242688), Vulkan runtime 1.4.325, SDK 1.4.328.1,
Visual Studio 2026 Insiders x64 compiler. Captures use native MSBuild Release;
Ninja Debug is built and captured separately. Python uses Pillow 12.1.1 and
NumPy 2.4.3. Vulkan validation and synchronization validation are enabled for
development captures. Existing unused vertex-input warnings remain; the measured
sequences contain no new VUID errors or synchronization hazards.

The renderer has two frame slots and retains its existing serialization of
shared GPU scene resources. This evidence proves history ordering under that
policy; it does not claim two overlapping GPU scene submissions. TAA adds no
device-wide idle to ordinary frames. Lifecycle recreation retires submitted work.

## Quality and reference method

The MIT-owned, embedded-buffer fixtures are generated by
[`generate_temporal_assets.py`](../tests/validation/generate_temporal_assets.py).
They include thin rotated edges, a moving specular cube, alpha checker holes,
overlapping glass layers, a moving emitter, mirrored/double-sided geometry,
newly uncovered surfaces and equivalent glTF/BIM/USD triangle geometry.

The camera-pan comparison uses 640 x 360 output and a 2560 x 1440 TAA-off
reference at the same keyframes. Reference samples are downsampled in linear
light. Metrics use the central scene ROI (U 0.25-0.75, V 0.16-0.74), retain the
thin edges/cube/wall, and exclude unrelated image boundaries. Residual flicker
measures the RMS change in error against the moving reference, so intended
motion does not count as shimmer. Detail is horizontal edge energy against
the reference; ghost persistence is reference MAE over the last four selected
frames, including occluder movement and stopping.

| Camera pan | TAA-off residual RMS | TAA-on residual RMS | Reduction | On/reference edge energy | Off/on reference MAE |
| --- | ---: | ---: | ---: | ---: | ---: |
| Deferred | 0.022925 | 0.020760 | 9.44% | 0.8660 | 0.006353 / 0.006064 |
| Forward | 0.023188 | 0.019927 | 14.06% | 0.9089 | 0.002256 / 0.002449 |

Moving-cube last-four-frame MAE is 0.006508 off / 0.006261 on in deferred and
0.002710 off / 0.002825 on in forward. The small forward increase is a measured
tradeoff, not a claim of perfect ghost removal. Thin boundary rejection limits
accumulation; this deliberately conservative first mode improves shimmer modestly.

The committed gates require flicker ratio below 0.95, edge energy above 0.65,
reference MAE at most `off * 1.3 + 0.002`, and moving-object ghost MAE at most
`off * 1.5 + 0.003`. Both techniques pass. These are fixture/platform budgets,
not universal image-quality guarantees. Covered OIT and emissive pixels use
current shading and therefore retain spatial aliasing. Deformation without
previous vertices, sky, native line/point overlays and layered refraction have
the documented current-frame fallback.

Actual GPU mutation runs verify the suite is sensitive to regressions:

| Deliberate mutation | Result |
| --- | --- |
| Invert velocity sign | Residual RMS increases to 0.022038; detected |
| Address stale history without motion | Residual RMS increases to 0.022010; detected |
| Skip reset invalidation | Expected reset-gray fraction becomes 0; detected |

The harness restores the original SPIR-V in `finally`; the restored resolve
SHA-256 is `ef8372f7d4af8dce3b0f3a50ca22ec6992eef507e99bda67287d62936cf2be65`.

## State, provider and lifecycle checks

CPU tests cover analytic projection and signed motion, separate history grids,
bounded zero-mean seeded jitter, successful-submission snapshots, discarded
preparation, reordered/recycled identities, local material revisions, padding,
camera cuts/projections and capture input validation. Material revisions are
cached per upload; snapshot map nodes are reused during stable scenes.

At the equivalent back-wall ROI, camera motion produces exactly the same
quantized signed velocity for glTF, BIM and USD: linear RGB
`[0.52711493, 0.50288492, 0.50288492]` (maximum difference 0). Provider root
translation, filtering/restoration, LOD policy and section changes are captured.
The stress suite also checks forward sidecar-only rendering, mixed primary/BIM
overlap, mirrored/double-sided and alpha-mask coverage, zero physical motion
under jitter, reset seeding and display exposure retaining the same epoch.

The 48-tick lifecycle sequence injects acquisition/presentation recovery,
skips rendering, minimizes/resumes, resizes between 640 x 360 and 800 x 450,
resets, switches technique and projection, changes TAA/MSAA and reloads the
scene. It produces exactly 45 successful submissions. TAA-off frames contain
no active temporal passes. Acquisition injection happens before real acquire;
presentation injection happens after real present, so both safely exercise the
recovery paths without manufacturing semaphore leaks. Tests preserve existing
GPU indirect drawing and require no added per-frame visibility readback.

The shared graph order is:
`Lighting -> TemporalVelocity -> TemporalResolve -> TransformGizmos -> Exposure -> OitPrepare -> Bloom -> PostProcess`.
Compose/resolve are timed together in `TemporalResolve`; OIT is composed exactly
once before history, and exposure/bloom/display conversion consume the result.
Raw diagnostic modes bypass jitter/TAA, while temporal debug views show the
scene history inputs. UI and editor transform/light gizmos use the stable camera.

## Performance and allocation budgets

Warm-up is 64 static frames; medians use the final three selected samples.
GPU totals are the sum of timestamped passes, not presentation/FPS. CPU submit
is queue submission only; screenshot encoding and readback are excluded.
Validation and small fixture size make these comparative measurements, not
production throughput promises. The 720p/1080p table is refreshed by the
performance suite before delivery.

| Resolution | Known GPU off/on (ms) | Velocity (ms) | Compose + resolve (ms) | CPU submit off/on (ms) | CPU scene off/on (ms) | Payload / actual VMA MiB |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 1280 x 720 | 1.048608 / 1.317984 | 0.043008 | 0.228160 | 0.1674 / 0.1889 | 0.0066 / 0.0125 | 132.71 / 141.56 |
| 1920 x 1080 | 2.276320 / 2.851904 | 0.110304 | 0.579264 | 0.1653 / 0.1822 | 0.0072 / 0.0123 | 298.61 / 318.52 |

History uses 40 bytes/pixel, plus 37 bytes/pixel for each swapchain image.
Three swapchain images produce 21 added image allocations and 151 bytes/pixel
of payload. Actual VMA bytes include alignment: 35.39 MiB at 640 x 360,
141.56 MiB at 1280 x 720, and 318.52 MiB at 1920 x 1080. Fresh TAA-off processes
allocate no temporal images. Resources are reused after disabling TAA.

Logical image writes are at least 57 bytes/pixel/temporal frame, excluding
texture reads, overdraw and metadata traffic. This is a bandwidth implication,
not measured hardware bandwidth: this GPU exposes timestamps but no usable
`VK_KHR_performance_query` backend. Conservative review budgets on this machine
are 0.35 ms temporal passes at 720p / 0.75 ms at 1080p, below 0.1 ms Release CPU
scene update, and below 170 / 400 MiB actual temporal image allocations. Future
format packing should be justified by quality and precision measurements.

## Builds, tests and reproduction

Ninja Debug and native Visual Studio MSBuild Release build the renderer and
temporal tests. The affected Debug CTest selection passes all 12 test programs:
29 temporal convention/state cases, 3 capture cases, 2 metric cases, the Slang
contract validation, 193 rendering conventions, 41 graph cases, 20 forward
technique/lighting cases, 14 provider extraction cases and 35 BIM routing cases.
All 73 runtime SPIR-V modules validate for Vulkan 1.4. Debug GPU captures also
pass synchronization validation.

The new temporal visual fixture passes the existing GPU harness, including its
TAA-off forward 1x/4x coverage check. The older Cornell golden/probes fail on
this machine: the stored image expects a darker blocker than the current
lighting. An unchanged pre-TAA Windows Release executable reproduces the same
failure, and its TAA-off Cornell capture is **pixel-identical** to the new build
(MAE 0, maximum byte difference 0). The historical golden is retained. This is
a pre-existing lighting/golden discrepancy, not a passing baseline test; its
capture, comparison metadata and failure log are included with the evidence.

Run builds from the Visual Studio Developer Console, then:

```powershell
ctest --test-dir out/build/windows-debug --output-on-failure -R "^(temporal_|render_graph_tests|rendering_convention_tests|forward_raster_.*tests|scene_provider_extraction_tests|bim_surface_pass_planner_tests|bim_surface_raster_pass_recorder_tests|bim_draw_compaction_planner_tests)"
$env:CONTAINER_RUN_TAA_REGRESSION = '1'
python -B tests/validation/temporal_regression.py --exe out/build/visual-studio/Release/VulkanSceneRenderer.exe --suite all
python -B tests/validation/temporal_regression.py --exe out/build/visual-studio/Release/VulkanSceneRenderer.exe --suite mutations --slangc C:/VulkanSDK/1.4.328.1/Bin/slangc.exe
```

GPU captures are opt-in. Missing Python metric dependencies return an explicit
skip, not a pass. Mutations must run without concurrent runtime staging or
captures. [`build-and-test.md`](build-and-test.md) documents packaging; the ZIP
contains the four new SPIR-V entry points and all temporal fixture assets.
Extracted-package verification and representative evidence are recorded in
[`tests/visual-regression/temporal/windows-nvidia`](../tests/visual-regression/temporal/windows-nvidia/).
That directory contains quality, stress, performance and mutation JSON plus
selected PNGs, configuration sidecars and the final CTest log. Full repeatable
sequences remain under `out/taa-regression` after running the commands above.

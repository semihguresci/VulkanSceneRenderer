# LTC validation on Windows / NVIDIA

These are untouched renderer captures and result records from October 9, 2026
on an RTX 2080 SUPER. The full matrix used synchronization validation, fresh
captures, and a fixed executable/source/SPIR-V/LUT snapshot. No earlier quality
images were reused. Numerical errors account for PNG quantization; they are
fixture measurements rather than general HDR error bounds.

`runtime-summary.json` records 232 launches and 238 primary records;
`spatial-results.json` contains 18 additional annulus records. The material
regression records 52 launches and 67 independent response/parity/lifecycle
checks. Both runs used the executable SHA recorded in their hash manifests.

The selected images show a sampled/LTC close-disk comparison at 25 samples,
forward/deferred radius-10 rim and layered-material pairs, and blocked/clear
disk soft shadows. Their original PNG hashes are in `capture-hashes.json`.
All fixtures are generated by the regression harness from repository assets.

Reproduce with the commands and interpretation guidance in
[LTC area lighting](../../../../docs/ltc-area-lighting.md). The extracted package
smoke results are recorded separately after a clean source checkpoint/build;
its executable revision stamp may differ, while shader and renderer sources
are checked against this matrix snapshot.

Rectangle integration accelerates the measured dense-light fixtures. Disk LTC
is slower than sampled integration on this GPU despite its near-field accuracy
improvement; see `validation-summary.json` for timings and measured limits.

The clean package was built from `d7eb6a25ae1170a405d9315e12a3980eb4fa17fd`.
`cpu-test-results.txt` records ten passing suites. All eight LTC and seven
temporal/provider/MSAA/ray package launches passed with SDK/Vulkan overrides
removed and Windows-only PATH. These runs disable validation, while the full
matrix above enables it. `package-build-info.json` binds the archive to its
91 executable/DLL/SPIR-V/LTC hashes; `package-SHA256SUMS.txt` records the ZIP
checksum. The original extracted payload stayed unchanged after both suites.

`package-build-equivalence.json` records the clean revision rebuild: executable
hash changed, renderer source and SPIR-V hashes stayed identical to the matrix.
Screenshot telemetry has no build revision field; that limitation is recorded
in the smoke results rather than presented as a captured revision check.
The ZIP is a local validation artifact, not a published GitHub release.
